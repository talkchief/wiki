This page covers the conventions that all TalkChief integration endpoints share: the base URL, the endpoint list, the response format, errors and rate limits. Request fields for each endpoint are documented on the [Click-to-Call](/developers/click-to-call) and [AI Transcription API](/developers/transcription-api) pages.

## Base URL

```text
https://api.talkchief.io/public/api
```

You can also find this URL in the TalkChief app under **Integrations** → **API** → **Overview & keys** → **Base URL**. Add the endpoint paths below to it.

## Endpoints

| Method | Path | Purpose | Authentication | Rate limit |
|---|---|---|---|---|
| `POST` | `/calls/click-to-call` | Ring a member and connect them to a destination | `api_key` in the body, or the `X-API-Key` header | 300 requests per minute |
| `POST` | `/ai/transcriptions` | Submit a recording for transcription | `X-AI-Api-Key` header | 120 requests per minute |
| `GET` | `/ai/transcriptions/{transcription_id}` | Get a transcription's status and result | `X-AI-Api-Key` header | 120 requests per minute |
| `GET` | `/ai/billing/balance` | Read your wallet balance | `X-AI-Api-Key` header | 120 requests per minute |
| `POST` | `/ai/billing/charge` | Debit your wallet for reconciliation. You don't need it for transcription, which bills itself | `X-AI-Api-Key` header | 120 requests per minute |

The CDR webhook isn't an endpoint you call. TalkChief sends call records to your endpoint. See [CDR webhook](/developers/webhooks).

## Request format

- Use HTTPS.
- Send JSON bodies with `Content-Type: application/json`. Click-to-Call also accepts form-encoded fields.
- Responses are JSON in UTF-8. Transcripts contain unescaped non-Latin text, such as Arabic or Hebrew.

## Response format

Every response has the same structure:

```json
{
  "success": true,
  "data": { },
  "message": null
}
```

When a request fails, `success` is `false`. The response adds a numeric `error_code`, and `errors` gives details for each field when there are any:

```json
{
  "success": false,
  "error_code": 400,
  "message": "Validation Error.",
  "errors": {
    "recording_url": ["The recording url field is required."]
  }
}
```

## How errors are reported

<Warning>
  Click-to-Call answers with **HTTP 200** for successful calls and for its own errors. Check `success` and `error_code` in the body. Requests over the [rate limit](#rate-limits) get HTTP `429` instead, before the request is processed, so check the HTTP status first. The AI endpoints use real HTTP status codes.
</Warning>

### Click-to-Call

Every processed request returns HTTP 200. For failures, `error_code` is a value from 404 to 418. Requests over the rate limit return HTTP `429` without a body in this format. The full list is in [Click-to-Call errors](/developers/click-to-call#errors).

### AI transcription and AI billing

| HTTP status | `message` | Meaning |
|---|---|---|
| `200` | | Success (poll, balance and charge) |
| `202` | | Transcription accepted. Also returned when you submit with `wait`, even if the job has already finished |
| `400` | `Validation Error.` or `recording_url must be an https URL` | A field is missing or malformed. Check `errors` |
| `401` | `UnAuthorised` | `X-AI-Api-Key` is missing, isn't 32 to 128 characters, or isn't recognized |
| `402` | `Error balance is below $5, please topup to proceed` | Transcription submit only. Your wallet balance is below the minimum. Nothing was submitted or charged |
| `402` | `insufficient balance` | Charge endpoint only. Your balance can't cover the amount |
| `403` | `company_id does not match the provided token` | Transcription submit only. `company_id` belongs to a different company than the key |
| `404` | `transcription not found` | Unknown ID, or the transcription belongs to another company |
| `502` | `billing system unavailable`, `transcription service unavailable` or `charge failed` | A temporary platform problem. Retry with backoff |

## Rate limits

Limits apply per minute (see the [endpoints](#endpoints) table). If you go over a limit, you get HTTP `429 Too Many Requests`. When that happens, wait and retry with exponential backoff and jitter. If the response includes a `Retry-After` header, wait at least that many seconds.

## OpenAPI specification

To get an OpenAPI 3.0 file covering Click-to-Call, AI Transcription, AI billing and the CDR webhook payload, go to **Integrations** → **API** → **OpenAPI Spec**. Click **Download JSON** to import it into Postman or Insomnia, or to generate a typed client. Click **Download PDF** for a printable reference.
