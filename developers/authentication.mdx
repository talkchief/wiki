Each TalkChief integration uses its own credential. Your company has one 64-character **Click-to-Call** key and one 64-character **AI Transcriber** key. Because the keys are separate, you can rotate one without affecting the other. The CDR webhook works the other way around: TalkChief calls your endpoint, and you choose the credential it sends.

| Integration | Credential | Where it goes |
|---|---|---|
| Click-to-Call | Click-to-Call API key | `api_key` field in the request body, or the `X-API-Key` header |
| AI Transcription and AI billing | AI Transcriber API key | `X-AI-Api-Key` header. Transcription requests also need your `company_id` |
| CDR webhook | A credential you choose (optional) | Sent by TalkChief to your endpoint as a bearer token, basic auth or a custom header |

<Note>
  None of these APIs use `Authorization: Bearer` with a TalkChief key. Bearer and basic auth only apply to webhook deliveries that TalkChief sends to your endpoint.
</Note>

## Generate a key

<Steps>
  <Step title="Open the API keys">
    Sign in as a company admin and go to **Integrations** → **API** → **Overview & keys**. Under **API Keys** there's one panel for **Click-to-Call** and one for **AI Transcriber**.
  </Step>
  <Step title="Generate the key">
    If a panel says **No key generated yet.**, click **Generate key**. Once the key exists, the panel shows **Active**.
  </Step>
  <Step title="Copy the key">
    Click **Show key** to reveal it, or click **Copy** to copy it. You can come back to this page any time to view the key again.
  </Step>
  <Step title="Note your Company ID (transcription only)">
    The **Company ID** appears at the top of **Integrations** → **API** → **Overview & keys**. Send it as `company_id` with AI Transcription requests.
  </Step>
</Steps>

## Send the key

<CodeGroup>

```bash Click-to-Call (body)
curl -X POST 'https://api.talkchief.io/public/api/calls/click-to-call' \
  -H 'Content-Type: application/json' \
  -d '{
    "api_key": "YOUR_CLICK_TO_CALL_KEY",
    "destination": "15555550123",
    "email": "agent@yourcompany.com"
  }'
```

```bash Click-to-Call (header)
curl -X POST 'https://api.talkchief.io/public/api/calls/click-to-call' \
  -H 'X-API-Key: YOUR_CLICK_TO_CALL_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "destination": "15555550123",
    "email": "agent@yourcompany.com"
  }'
```

```bash AI Transcription
curl -X POST 'https://api.talkchief.io/public/api/ai/transcriptions' \
  -H 'X-AI-Api-Key: YOUR_AI_TRANSCRIBER_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "company_id": 1234,
    "recording_url": "https://example.com/recordings/call.mp3"
  }'
```

</CodeGroup>

If you send `api_key` in the body and the `X-API-Key` header together, Click-to-Call uses the body value.

## What happens when a key is wrong

The two APIs report key problems differently.

| API | Problem | Response |
|---|---|---|
| Click-to-Call | No key sent | HTTP 200, `success: false`, `error_code: 405`, `"api_key is required."` |
| Click-to-Call | Key isn't 64 characters | HTTP 200, `success: false`, `error_code: 406`, `"api_key is invalid."` |
| Click-to-Call | Key doesn't match any company, for example because it was rotated | HTTP 200, `success: false`, `error_code: 413`, `"api_key is invalid."` |
| AI Transcription and AI billing | Header missing, wrong length or unknown key | HTTP 401, `"UnAuthorised"` |
| AI Transcription | `company_id` belongs to a different company than the key | HTTP 403, `"company_id does not match the provided token"` |

Click-to-Call answers successful calls and the errors above with HTTP 200, so check `success` and `error_code` in the response body. A request that goes over the rate limit is rejected with HTTP `429` before it is processed, so check the HTTP status first. See [REST API conventions](/developers/rest-api) for both response formats.

## Rotate a key

<Steps>
  <Step title="Start the rotation">
    In **Integrations** → **API** → **Overview & keys**, click **Rotate key** on the panel you want to rotate.
  </Step>
  <Step title="Confirm">
    The dialog warns that the current key stops working immediately. Click **Confirm rotation**.
  </Step>
  <Step title="Update your integration">
    Copy the new key into your backend configuration and reload it. Requests that still use the old key fail right away.
  </Step>
</Steps>

<Warning>
  Rotation takes effect immediately and there's no grace period. Schedule it at a time when you can deploy the new key straight away.
</Warning>

You can't delete a key from the app. To revoke a leaked key, rotate it.

## Security practices

- Keep keys on your server. Never put them in browser JavaScript, mobile apps or public repositories.
- Store keys in environment variables or a secrets manager.
- If you think a key has leaked, rotate it right away.
- For the CDR webhook, use HTTPS and turn on one of the authentication options. Your endpoint can then reject requests that don't come from TalkChief. See [CDR webhook](/developers/webhooks#authenticate-deliveries).
