The CDR webhook sends a call detail record (CDR) to your endpoint after each call ends. You get one delivery per call, with the direction, outcome, timings, the agent who handled it and a link to the recording if there is one. Use it to keep a CRM, data warehouse or billing system up to date without polling.

There's one event type: **call completed**. You don't subscribe to individual events.

## Set up the webhook

<Steps>
  <Step title="Open the webhook settings">
    Sign in as a company admin and go to **Settings** → **Integrations** → **CDR Webhook**. Until you save a webhook, the status shows **Not configured**.
  </Step>
  <Step title="Enter your endpoint">
    In **Endpoint URL**, enter the full `http://` or `https://` address of your receiver, up to 1,024 characters. It must be reachable from the public internet. Use HTTPS in production.
  </Step>
  <Step title="Choose method, body format and retries">
    - **Method**: `POST` (default), `PUT` or `GET`. `GET` sends the fields in the query string and ignores the body format.
    - **Body format**: **JSON** (default) or **Form data** (`application/x-www-form-urlencoded`).
    - **Retry attempts**: 0 to 5. The default is 3.
  </Step>
  <Step title="Choose authentication (optional)">
    Under **Authentication**, choose an **Authentication type**: **None**, **Bearer token**, **Basic auth** or **Custom header**. Then fill in the fields it shows. See [Authenticate deliveries](#authenticate-deliveries).
  </Step>
  <Step title="Save">
    Click **Enable webhook**. Saving turns delivery on, and the status changes to **Active**. Later edits use **Save changes**.
  </Step>
</Steps>

Once the webhook exists, the page also shows **Disable** (switch delivery off and keep your settings), **Enable** (switch it back on) and **Delete webhook** (remove the webhook and its endpoint URL). After you delete it, calls are no longer delivered.

<Note>
  Calls between two internal extensions aren't delivered. The webhook only reports calls with an outside party.
</Note>

## Authenticate deliveries

TalkChief doesn't sign webhook requests. To check that a request came from TalkChief, set a credential that TalkChief sends with every delivery, and have your endpoint check it.

| Authentication type | Fields in the app | Header your endpoint receives |
|---|---|---|
| **None** | | No authentication header |
| **Bearer token** | **Token** | `Authorization: Bearer <token>` |
| **Basic auth** | **Username**, **Password** | `Authorization: Basic base64(username:password)` |
| **Custom header** | **Header name**, **Header value** | `<Header name>: <Header value>` |

- The credential is one your endpoint expects. It's not a TalkChief API key.
- Secrets can be up to 2,048 characters and can't contain line breaks. A basic auth username can't contain a colon.
- A custom header name can only contain letters, digits and ``! # $ % & ' * + . ^ _ ` | ~ -``. You can't use `Host`, `Content-Length`, `Content-Type`, `Transfer-Encoding`, `Connection`, `User-Agent` or `Accept`, because TalkChief sets these itself.
- You enter the secret but never see it again. The app only shows that a secret is saved, plus its last four characters for longer secrets. If you leave the field blank when you save, the stored secret is kept, as long as you haven't changed the authentication type.
- If you switch the type to **None** and save, the stored credential is removed.
- TalkChief never follows redirects, so the credential only ever goes to the exact endpoint you entered.

## Payload

Every delivery contains these fields. With JSON, the body is UTF-8, and non-Latin names arrive as readable text, not escape codes. With form data or `GET`, `null` values are sent as empty strings and booleans as `true`/`false`.

```json
{
  "providerCallId": "2d489b415666b49444c2395700bcfd82@acme.talkchief.io",
  "direction": "outbound",
  "status": "answered",
  "from": "501",
  "to": "+15555550123",
  "startedAt": "2026-07-30T14:22:27+03:00",
  "answeredAt": "2026-07-30T14:22:42+03:00",
  "endedAt": "2026-07-30T14:22:53+03:00",
  "durationSeconds": 11,
  "ringingSeconds": 4,
  "totalSeconds": 26,
  "agentExtension": "501",
  "agentName": "Jane Doe",
  "agentEmail": "agent@yourcompany.com",
  "agentTeam": "Sales",
  "legCallId": "a1b2c3d4-0000-0000-0000-000000000000",
  "callerName": "John Smith",
  "recording": null,
  "recordingAvailable": false,
  "queue": null,
  "hangupCause": "NORMAL_CLEARING",
  "hangupCode": "200",
  "accountId": "0123456789abcdef0123456789abcdef"
}
```

### Fields

<ResponseField name="providerCallId" type="string" required>
  A stable, unique ID for the call. Use it to deduplicate. If a call is delivered again, it has the same `providerCallId`.
</ResponseField>

<ResponseField name="direction" type="string" required>
  `inbound` or `outbound`.
</ResponseField>

<ResponseField name="status" type="string" required>
  One of `answered`, `busy`, `no-answer`, `cancelled`, `abandoned`, `voicemail`, `congestion` or `failed`. `abandoned` means an inbound caller hung up before anyone answered. `cancelled` is the outbound equivalent.
</ResponseField>

<ResponseField name="from" type="string" required>
  The calling number, in E.164 format when it's a real phone number. Internal extensions appear exactly as dialed.
</ResponseField>

<ResponseField name="to" type="string" required>
  The called number. Same format as `from`.
</ResponseField>

<ResponseField name="startedAt" type="string" required>
  When the call started, in ISO 8601 with a UTC offset, in your account's time zone.
</ResponseField>

<ResponseField name="answeredAt" type="string | null">
  When the call was answered. `null` if it was never answered.
</ResponseField>

<ResponseField name="endedAt" type="string | null">
  When the call ended.
</ResponseField>

<ResponseField name="durationSeconds" type="integer" required>
  Billed talk time, in seconds. It doesn't include ringing, so it's not `endedAt − startedAt`. `endedAt − answeredAt` always equals `durationSeconds`.
</ResponseField>

<ResponseField name="ringingSeconds" type="integer">
  How long the call rang, as the phone platform reports it. A call has several legs and this figure covers only one of them, so it may not equal `answeredAt − startedAt`.
</ResponseField>

<ResponseField name="totalSeconds" type="integer">
  The whole call including ringing. Always equals `endedAt − startedAt`.
</ResponseField>

<ResponseField name="agentExtension" type="string" required>
  Extension of the member who answered an inbound call or placed an outbound one.
</ResponseField>

<ResponseField name="agentName" type="string | null">
  The member's name, in UTF-8.
</ResponseField>

<ResponseField name="agentEmail" type="string | null">
  The member's email address. Unlike the extension, it's a stable identifier.
</ResponseField>

<ResponseField name="agentTeam" type="string | null">
  The team the member belongs to.
</ResponseField>

<ResponseField name="legCallId" type="string | null">
  The ID of one underlying call leg. For troubleshooting only. Don't deduplicate on it, because one call has several legs.
</ResponseField>

<ResponseField name="callerName" type="string | null">
  The caller ID name as it was shown, in UTF-8.
</ResponseField>

<ResponseField name="recording" type="string | null">
  The URL of the call recording, if there is one. Calls with no talk time never include a recording.
</ResponseField>

<ResponseField name="recordingAvailable" type="boolean" required>
  `true` exactly when `recording` contains a URL.
</ResponseField>

<ResponseField name="queue" type="string | null">
  The queue the call came through, if any.
</ResponseField>

<ResponseField name="hangupCause" type="string | null">
  The raw hang-up cause from the phone platform, for example `NORMAL_CLEARING`.
</ResponseField>

<ResponseField name="hangupCode" type="string | null">
  The SIP response code, for example `200` or `486`.
</ResponseField>

<ResponseField name="accountId" type="string | null">
  Your account ID on the TalkChief phone platform.
</ResponseField>

<Tip>
  To transcribe a delivered call, send its `recording` URL to the [AI Transcription API](/developers/transcription-api).
</Tip>

## Respond and handle retries

- Reply with any `2xx` status to acknowledge a delivery. Each attempt waits up to 15 seconds for your reply.
- TalkChief retries when it can't connect, when the request times out, or when you reply with `408`, `425`, `429` or any `5xx`. Retries are spaced further apart each time: after 30 seconds, 2 minutes, 10 minutes, 30 minutes and 1 hour. **Retry attempts** sets how many of these steps are used. A value of 0 is treated as the default of 3.
- Any other `4xx` reply, such as `400`, `401`, `404` or `422`, counts as a permanent failure, and that call isn't retried.
- If your endpoint keeps failing, the webhook can be switched off automatically. The CDR Webhook page then shows **Disabled** and the reason. Fix the endpoint and click **Save changes** to switch it back on.

Each call arrives once in normal operation. A delivery that TalkChief couldn't confirm may be sent again, though, so always deduplicate on `providerCallId`.

## Timing

TalkChief waits about 90 seconds after a call ends before delivering it. This lets every part of the call, including the recording, be combined into one record. Expect each record to arrive roughly a minute and a half to two minutes after the call ends.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The page says Agent details are missing">
    Member information isn't being attached to deliveries. Click **Save changes** on the CDR Webhook page to restore it.
  </Accordion>
  <Accordion title="The page says Other webhooks may deliver duplicate calls">
    Another webhook on your account also reports completed calls, so the same call can reach you twice. The page lists the other webhooks by name and address. If you don't recognize one, contact TalkChief support.
  </Accordion>
  <Accordion title="My endpoint receives no authentication header">
    Check that the authentication type isn't **None** and that a secret is saved. If a stored value is malformed, TalkChief sends no authentication header at all rather than a broken one, so your endpoint should reply `401`.
  </Accordion>
  <Accordion title="recordingAvailable is false for an answered call">
    The recording wasn't ready in time to include it. The record isn't updated later. Recordings are only sent for calls that were recorded and had talk time.
  </Accordion>
</AccordionGroup>
